# All India Café — Customer Experience Intelligence System

A vertical touchscreen at the café exit collects feedback; an admin app turns it
into decisions. Built by Vibrnd. The full specification is in
[CLAUDE.md](./CLAUDE.md) — it is the source of truth, and this file only covers
how to run and operate what it describes.

- **Kiosk** — `/` (public, anonymous, portrait 1080×1920)
- **Admin** — `/admin` (email + password, four roles)

---

## Setup

Requires Node 20+ and pnpm.

```bash
pnpm install
cp .env.example .env.local     # then fill it in, see below
pnpm migrate                   # applies supabase/migrations in order
pnpm create-user you@example.com OWNER "Your Name"
pnpm dev
```

`create-user` prints a generated password once. Change it after signing in.

### Environment

| Variable | Where it is used | Notes |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | browser + server | Safe to expose. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | browser + server | Safe to expose. RLS applies. |
| `SUPABASE_SERVICE_ROLE_KEY` | **server only** | Bypasses RLS. Never prefix with `NEXT_PUBLIC_`. |
| `NEXT_PUBLIC_OUTLET_CODE` | server | Which outlet this deployment serves. Defaults to `AIC`. |
| `SUPABASE_DB_URL` | `pnpm migrate` only | Direct Postgres connection. |
| `CRON_SECRET` | retention purge | The purge refuses to run without it. |

> The Supabase **direct** connection (`db.<ref>.supabase.co`) is IPv6-only. On an
> IPv4-only network use the **session pooler** host instead:
> `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`

## Migrations

Numbered SQL in `supabase/migrations/`, applied in filename order by
`scripts/migrate.mjs`, which keeps a `schema_migrations` ledger with a checksum
per file.

| File | What it does |
|---|---|
| `0001_core_schema.sql` | Every table, index, constraint, trigger and code generator. |
| `0002_seed.sql` | The outlet, categories, rating scale, chips, theme lexicon and all §5 copy. |
| `0003_rls.sql` | Row Level Security and the §8 role matrix. |
| `0004_aggregate_views.sql` | Analytics views (all `security_invoker`). |
| `0005_trigger_privileges.sql` | Makes the maintenance triggers `SECURITY DEFINER`. |
| `0006_retention_and_rate_limit.sql` | Retention purge and the kiosk write budget. |

```bash
pnpm migrate          # apply pending
pnpm migrate:status   # what is applied, what is pending
```

**Never edit a migration that has been applied.** The runner compares checksums
and refuses, because a repo and a database that disagree about the schema is a
worse problem than an extra file. Write a new migration instead.

After any migration:

```bash
pnpm gen              # regenerates types/database.ts and the config fallbacks
```

## Commands

| Command | What it does |
|---|---|
| `pnpm dev` | Development server. |
| `pnpm build` | Production build. |
| `pnpm test` | Full suite. DB tests run against PGlite, no Supabase needed. |
| `pnpm typecheck` | `tsc --noEmit`. |
| `pnpm lint` / `pnpm format` | ESLint / Prettier. |
| `pnpm migrate` | Apply migrations. |
| `pnpm gen` | Regenerate `types/database.ts` and config defaults. |
| `pnpm create-user <email> <ROLE> [name]` | Create an admin-app account. |

`pnpm gen` is not optional after a schema change: `types/database.ts` is
generated by introspecting a real Postgres with the migrations applied, and
stale types silently infer `never`.

## Deploying to Vercel

1. Import the repository.
2. Add every variable from the table above as a Project Environment Variable.
   Double-check `SUPABASE_SERVICE_ROLE_KEY` is **not** prefixed `NEXT_PUBLIC_`.
3. Deploy. `vercel.json` already registers the nightly retention purge
   (20:00 UTC = 01:30 IST, after closing).
4. Point `feedback.allindiacafe.in` at the deployment.

Every kiosk and admin route is `force-dynamic` on purpose. The kiosk reads all
its copy from the database, so a prerendered page would need a redeploy to show
a CMS edit; admin pages are per-user and must never be cached across people.

## Kiosk tablet setup

1. **Portrait lock** in the tablet's display settings, and disable auto-rotate.
2. Open `https://feedback.allindiacafe.in` in a kiosk-mode browser
   (Chrome: *Add to Home screen*, then launch from there for fullscreen; or
   Fully Kiosk Browser on Android for lock-task mode).
3. **Disable sleep** and set the screen to stay on while charging.
4. **Auto-restart**: schedule a nightly reboot, and set the kiosk browser to
   launch on boot with this URL as its home page.
5. Leave it plugged in. The app pings a heartbeat every two minutes, and the
   dashboard shows the terminal as offline if it stops.

The app already blocks zoom, text selection, right-click, pull-to-refresh and
overscroll, resets to Welcome after 90 seconds of inactivity, and queues
submissions in IndexedDB if the wifi drops — the guest still sees their
thank-you, and the queue drains when the connection returns.

## Manager's guide

**Today at a Glance** (`/admin`) answers "what is happening right now". Read it
top to bottom: alerts, then the KPI row, then *What needs attention?*, which the
system writes itself from the data. Every card links to the feedback behind it.

**Analytics** answers "what is happening over time" — trends, category
performance, what guests are complaining about and praising, and how the
experience differs by time of day and day of week. A gap in a line means no
feedback that day, not a zero.

**Feedback** is every submission, filterable. The filters live in the URL, so a
view worth showing someone can be sent as a link.

**Guests** is the same people over time. The Experience Journey on a profile
tells you whether a returning guest is getting happier or quietly giving up.

**Settings** is where you change things, and you do not need a developer:

- **Kiosk content** — every word the guest reads, with a live preview. Each
  field has *Reset*, which restores the wording that was originally approved.
- **Categories, issues and themes** — what guests rate and pick. Deactivate
  rather than delete; past feedback keeps working either way.
- **Rating scale** — the five faces, their labels and colours.
- **Branding** and **Grievance officer** — the footer, and the number a guest
  can call. **Replace the placeholder number before go-live.**
- **Thresholds, alerts and privacy** — when the dashboard raises its voice, and
  how long contact details are kept.

Two things worth knowing:

- Editing the theme keywords only affects **new** comments until you press
  *Re-scan past comments*.
- Phone numbers are masked everywhere. Revealing one is a deliberate click and
  is recorded against your name.

## Testing

```bash
pnpm test
```

212 tests. The database tests apply the real migrations to PGlite (Postgres
compiled to WASM) and run as the `authenticated` role, so RLS and trigger
privileges are actually exercised rather than assumed — a trigger that works as
the table owner and fails under RLS is exactly the bug that shipped once here
and now has a regression test.

The seed test re-reads §5 of `CLAUDE.md` on every run and fails if any
customer-facing string has drifted from the approved wording.
